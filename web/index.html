The problem

Analysts, researchers, and journalists lean on AI for research — but LLMs hallucinate citations, quote numbers without checking them, and leave no trail of what actually happened. One wrong number in a report costs trust.

Trace fixes this with architecture, not vibes: a six-stage pipeline with deliberate model tiering, claim-by-claim verification against extracted sources, sandbox-recomputed statistics, scoped tool permissions per stage, and a human-approval gate before anything leaves draft. Every tool call, model tier, and latency lands in a JSONL audit trail — the brief carries its own receipts.

2 · The brief it produced

# Research brief: How do frontier coding agents verify the code they write?

## 1. Tests first, trust later

Frontier coding agents verify code primarily by executing it: reproducing failing
tests, applying a patch, and re-running the suite until green [1][3].
Self-critique alone is unreliable.

## 2. Published harnesses set the bar

SWE-bench Verified reports top agent pass rates of 74.7%, while SWE-bench
Multimodal drops to 41.9% — a 32.8 percentage-point gap recomputed in our
sandbox [1][2][sandbox:t1].

## 3. Failure modes

LLM self-verification fails when the same model grades its own work without
external execution; calibration is restored by independent test runs in
isolated sandboxes [3].

## Verification

- Agents verify code by executing tests in sandboxes — confidence 0.92 ✅
- 74.7% vs 41.9% pass rates, 32.8pp gap — confidence 0.97 ✅
- Self-critique alone is unreliable — confidence 0.88 ✅

Nemotron tiering, on purpose

All inference goes through Nebius Token Factory via its OpenAI-compatible endpoint (https://api.tokenfactory.nebius.com/v1) with NEBIUS_API_KEY. Each pipeline stage is mapped to a Nemotron tier in trace/config.py — swap model IDs without touching code.

StageModel (live on Token Factory)ReasoningWhy
PLANnvidia/nemotron-3-super-120b-a12bonHeavy multi-step decomposition, 1M context, native tool calling
DRAFTnvidia/nemotron-3-nano-30b-a3blowHigh-volume section writing — fast and cheap
VERIFYnvidia/nemotron-3-super-120b-a12bonCareful claim-by-claim checking against sources

Why this wins: it is the deliberate use of NVIDIA open models the hackathon asks for — reasoning-heavy Super 120B where judgment matters, cheap Nano 30B where volume matters — all over one OpenAI-compatible Token Factory client.

  • Tavily powers retrieval: search (advanced depth) per research question plus extract for full source text the verifier checks claims against — also the basis of the Best Use of Tavily prize entry.
  • Token Factory Sandboxes execute the generated data-analysis jobs: static safety gate first, then isolated cloud microVM via the account's sandbox endpoint (or TRACE_SANDBOX_BACKEND=local for dev/tests).
  • Observability is structural: audit trail records run IDs, input hashes, model IDs, backends, and latencies for every stage.

Audit & governance, built in

Scoped tool permissions per stage (trace/policy.py) — a stage physically cannot call another stage's tools, so a creative or compromised model output can't exfiltrate data or run code where it shouldn't.

StageAllowed tools
planllm:planner
searchtavily:search
extracttavily:extract
analyzesandbox:execute
draftllm:drafter
verifyllm:verifier, tavily:extract
approvehuman:approve
assemblenone — pure local code, no tools
  • Human-approval gate: no brief leaves “draft” until a human approves it; the approval and note are recorded in the audit trail.
  • JSONL audit trail in runs/: every run, every stage, every decision — inspectable after the fact.
  • Safety-gated sandbox: generated code passes a static gate (allowlisted imports, no dangerous builtins, bounded timeout) before it can execute anywhere.

Run it yourself

$ git clone https://github.com/solanaminter/trace-research
$ cd trace-research
$ python -m venv .venv && source .venv/bin/activate
$ pip install openai pytest requests

# Offline demo (deterministic mock shim, no keys):
$ TRACE_MOCK=1 python -m trace.cli research "your question" --auto-approve

# Live run (see NEBIUS_SETUP.md):
$ export NEBIUS_API_KEY="..."            # Token Factory key
$ export TAVILY_API_KEY="..."            # Tavily key
$ export TRACE_SANDBOX_BACKEND=tokenfactory
$ export NEBIUS_SANDBOX_URL="..."        # sandbox endpoint
$ python -m trace.cli research "your question"   # draft until YOU approve it

Honest framing, same as the README: the video and tests run on the deterministic mock shim — the integration code paths (Token Factory inference, sandboxes, Tavily) are real and exercised by the 11-test suite, and they go live the moment the keys are set.
